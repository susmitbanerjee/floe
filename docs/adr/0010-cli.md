# 0010. The floe command line: output, failures and shutdown

- Status: Accepted
- Date: 2026-11-20

## Context

Prompt 9 joins the libraries into `floe serve` and `floe config check`, with three goals:
- one line per startup step;
- every failure explained in one line with a fix;
- an exit code a service manager can act on.

Its design named three output functions (`ok`, `fail`, `next`) and an `app::run(config, deps,
shutdown)`. It also asked for a shutdown that waits up to 10 s and logs how many queries were
drained and cancelled.

## Decision

**Output** (`cli/output.rs`, the only module that prints):
- **Four functions.** `ok`, `fail` and `next` from the prompt, plus `ready` for the connection
  URL line that the prompt's startup sequence shows.
- **Layout.** Tags are padded to 7 characters, labels to 10, and elapsed times start at
  column 57, so lines align.
- **Streams.** Startup lines go to stdout; failures go to stderr, so `floe config check
  > /dev/null` still shows them.
- **No colour in phase 1, anywhere.** clap's `color` feature and tracing-subscriber's `ansi`
  feature are off. The CLI tests check that no escape code appears, with and without NO_COLOR,
  so the v0.1 styling must keep plain output for pipes and NO_COLOR.

**Failures** (`cli/failure.rs`):
- **Every error says what and fix separately.** `ConfigError`, `CatalogError` and `AppError`
  each have a Display (what happened and why) and a `fix()` (what to do).
- **One line each.** A failure prints `fail <label> <what>`, then `fix: …` under it.
- **Exit codes** come from sysexits.h, and `--help` lists them:

  | Code | Meaning |
  |---|---|
  | 0 | ok |
  | 2 | bad usage (clap) |
  | 69 | catalog unreachable or unauthorised |
  | 70 | internal error |
  | 71 | cannot bind the listener |
  | 78 | config invalid |

- **`CatalogError::Unauthorized` gained `status` and `uri`**, to read
  `HTTP 401 from https://…`.
- **`NoAwsCredentials` became its own variant,** because it isn't an HTTP answer.

**App** (`app.rs`):
- **`start` and `Started::serve`.** `run` is the two together. Tests start on port 0, read the
  bound address, then serve; `floe serve` calls `run`.
- **`Deps { catalog }`** carries the connected catalog. The CLI connects it, so a connect
  failure is a catalog failure (69).
- **`LakeCatalogProvider::refresh`** now returns how many namespaces and tables it found.

**Shutdown:**
- SIGINT and SIGTERM cancel the token.
- floe-pg's drain now waits `ServerSettings.shutdown_grace` (10 s, set by the config loader)
  instead of the statement timeout plus 5 s. It then aborts the remaining connections, which
  cancels their statements.
- `serve_on` returns a `ShutdownSummary`, and the app logs it as one info line: `Floe stopped:
  1 query drained, 0 cancelled`.

**Logging:**
- tracing to stderr, as `--log-format text|json`.
- `--log-level` is the default, and RUST_LOG wins.

## Consequences

- **Testing.** Errors with separate fixes changed some message wording; tests now check
  `fix()`. Failures are easy to test and to style later.
- **A second Ctrl-C doesn't force an exit yet.** The drain is bounded at 10 s anyway.
- **Cancel during shutdown is a connection abort.** Clients see the connection close rather
  than a 57P01 message, because pgwire can't inject one into an idle connection.
- **Not built:** daemon mode and PID files. Use systemd or a container.
